1) I costruttori sono crea() e aggiungi(Lista, Elemento) -> Lista.
Declare: L, L': Lista; e, e': Elemento; i: Intero

Assumo: +(Intero, Intero) -> Intero

Operatore leggi(Lista, Intero) -> Elemento:
- leggi(crea(), i) = error
- leggi(aggiungi(L, e), i) =
	if i == dim(L) + 1 then e else leggi(L)

ove dim(Lista) -> Intero:
- dim(crea()) = 0
- dim(aggiungi(L, e)) = 1 + dim(L)

Operatore conta(Lista, Elemento) -> Intero:
- conta(crea(), e) = 0
- conta(aggiungi(L, e), e') = if e = e' then 1 + conta(L) else conta(L)

Operatore suffisso(Lista, Intero) -> Lista:
- suffisso(crea(), i) = crea()
- suffisso(aggiungi(L, e), i) =
	if < 0 or i > 1 + dim(L) then
		error
	else
		if i == 0 then crea()
		else aggiungi(suffisso(L, i - 1), e)

Operatore combina(Lista, Lista, Intero) -> Lista:
- combina(crea, L', i) = suffisso(L', i)
- combina(aggiungi(L, e), L', i) = concatena(suffisso(aggiungi(L, e), i), suffisso(L'))

ove concatena(Lista, Lista) -> Lista:
- concatena(crea(), L') = L'
- concatena(aggiungi(L, e), L') = aggiungi(concatena(L, L'), e)

2) L'astrazione di tipo è una tecnica di programmazione di supporto all'astrazione dati. Le tecniche di supporto all'astrazione dati, infatti, sono due:
- creazione di tipi di dato astratti che permettono di astrarre sulla classe sintattica tipo;
- creazione di classi di oggetti che permette di astrarre sulla dichiarazione di un modulo dotata di stato interno.
L'astrazione di tipo mette a disposizione dell'utente un identificatore di tipo e un insieme di operatori applicabili su di esso. L'astrazione di tipo possiamo specificarla come segue:
type I(FP1, ..., FPn) is E
ove I è un'identificatore, FP1, ..., FPn sono parametri formali ed E rapprsenta una rappresentazione concreta del tipo che si sta definendo.
Per poter realizzare al meglio l'astrazione di tipo, la realizzazione del tipo di dato astratto non deve essere visibili al fruitore esterno. Occorre quindi incapsulare la rappresentazione dei dati con il loro utilizzo ed è possibile fare ciò mediante la creazione di un modulo. In Ada il modulo prende il nome di package che è composto da due parti:
- la specification che contiene la dichiarazione di costanti, di procedure, di funzioni e di tipi. La specification a sua volta si divide in parte pubblica che contiene dati o operazioni che possono essere utilizzate anche all'esterno e parte privata che contiene dati o operazioni interni al modulo.
L'identificatore di tipo viene creato con la parola chiave private e la realizzazione viene definita nella parte private della specificiation. Inoltre, se si vogliono inibire operazioni di assegnazione e confronto fornite di default dal compilatore si può dichiarare il tipo astratto come limited private.
- il body che contiene l'implementazione dei metodi dichiarati nella specification e talvolta, una routine di inizializzazione del package.

Inoltre, in Ada è possibile anche parametrizzare un package ottenendo il cosidetto generic package. I parametri possibili che si possono passare ad un generic package sono di due tipi:
- parametri di valore: come ad esempio la capacità massima di un array;
- parametri di tipo: permettono di passare il tipo di dato come paraemtro formale, i valori dei parametri verranno poi formalizzati quando verrà istanziato il generic package.
L'astrazione generica è utile in quanto se, ad esempio, c'è necessità di creare una Pila di Interi, una Pila di Stringhe e una pila di Caratteri, il programmatore dovrebbe creare tre moduli separati, ma con l'astrazione generica e i parametri di tipo viene creato un solo modulo e sarà poi il compilatore a controllare la correttezza dei tipi e a creare i moduli per le tre istanze del package.
Per istanziare un generic package in Ada la sintassi è la seguente:
package prova is new noemGenericPacakge(...)
e questa linea di codice verrà processata in fase di precompilazione e verrà sostituita con il comando di importazione di un package e il compilatore verificherà staticamente la correttezza dei parametri formali con quelli effettivi.
Inoltre, il compilatore per ogni istanziazione del generic package crea una copia del codice del package per quel determinato tipo e questo comporta inefficienza in spazio ma efficienza in tempo in quanto i legami vengono risolti a compile-time.

generic
	max: Positive;
	type Elemento is private;
package TypeLista
begin
	type Lista is limited private;
	procedure aggiungi(l: in out Lista, e: in Elemento);
	function leggi(l: in Lista, i: in Integer) return Elemento

	private
		type Lista is record
			top: Integer range of (0..max) = 0;
			valori: Array (1..max) of Elemento;
		end record
end TypeLista

package body TypeLista
begin
	procedure aggiungi(l: in out Lista, e: in Elemento)
	begin
		if l.top == max then raise "Eccezione";
		else
			l.top := l.top + 1;
			l.valori(l.top) := e;
	end

	function leggi(l: in Lista, i: in Integer) return Elemento
	begin
		if i < 0 or i > l.top then raise "Eccezione"
		else
			return l.valori(i);
	end
end TypeLista

with TypeLista;
package IntLista is new TypeLista(100, Integer);
package CharLista is new TypeLista(100, Character);
with IntLista; use IntLista;
with CharLista; use CharLista;

L1: IntLista;
L2: CharLista;

aggiungi(L1, 1);
aggiungi(L1, 10);
aggiungi(L2, 'a');
aggiungi(L2, 'b');
aggiungi(L2, 'c');

3) Il meccanismo di gestione delle eccezioni in Java permette di separare la normale esecuzione del programma dalla cattura e gestione di situazioni anomale che si generano a run-time.
In Java le eccezioni sono degli oggetti e sono istanza della classe Throwable che si suddivide in due classi:
	- la classe Exception usata per le condizioni eccezionali che il programma utente dovrebbe catturare. A sua volte la classe Exception contiene delle eccezioni controllate che derivano direttamente da Exception e il programmatore è obbligato a gestirle e le eccezioni non controllate che derivano dalla classe RuntimeException e il programmatore non è obbligato a catturarle e gestirle.
	- la classe Error che definisce le eccezioni da catturare in circostanze normali nel programma.

Nel linguaggio Java per creare e lanciare un'eccezioni si utilizza la clausola throw new ThrowableInstance(msg) ed è bene non confonderla con la clausola throws ExceptionLists che invece viene usta nella dichiarazione di un metodo per indicare quali eccezioni potrebbe generare quel metodo. Se un metodo contiene porzioni di codice che potrebbero generare eccezioni controllate la dichiarazione del metodo deve necessariamente contenere la clausola throws. Per gestire un'eccezione in Java si utilizza la sintassi del try-catch-finally. Nella sezione try viene inserita la porzione di codice che potrebbe lanciare delle eccezioni. Se in un metodo try viene lanciata un'eccezione questa deve essere catturata e gestita. Per fare ciò, si esce dal blocco try e si cerca il rispettivo blocco catch che ha come argomento il tipo di eccezione da gestire. Dopo aver trovato il rispettivo metodo catch si esegue la porzione di codice all'interno del blocco catch. Ad un blocco try ci possono essere più blocchi catch in quanto un metodo può lanciare più eccezioni di tipo differente. La clausola finally invece contiene una porzione di codice che viene eseguita indipendentemente da come si è usciti dal blocco try.

Il linguaggio Java permette anche di definire nuove eccezioni controllate e non, estendendo rispettivamente la classe Exception o RuntimeException.

class Elemento {
	private int codice;
	privagte String valore;

	Elemento(int codice, String valore) {
		this.codice = codice;
		this.valore = valore;
	}
}

class Lista {
	private List<Elemento> valori;

	Lista() {
		valori = new ArrayList<>();
	}

	void aggiungi(Elemento e) {
		valori.add(e);
	}

	Elemento leggiControllata(int i) throws CheckedException {
		if (i < 0 || i > valori.size(i)) {
			throw new CheckedException("Controllata");
		}
		return valori.get(i);
	}

	Elemento leggiNonControllata(int i) {
		if (i < 0 || i > valori.size())
			throw new UncheckedException("Non controllata");
		valori.get(i);
	}
}

class CheckedException extends Exception {
	public CheckedException(String msg) {
		super(msg);
	}
}

class UncheckedException extends RuntimeException {
	public UncheckedException(String msg) {
		super(msg);
	}
}

class Main {
	public void main(String[] args) {
		Lista l = new Lista();

		l.aggiungi(new Elemento(1, "prova"));
		l.aggiungi(new Elemento(2, "prova2"));

		try {
			l.leggiControllata(1);
		} catch CheckedException {
			System.err.println(e.getMessage());
		}
		l.leggiNonControllata(2);
	}
}

In java la parola chiave final ha significati diversi a seconda di dove viene utilizzata. Quando final viene applicato ai dati bisogna fare distinzione tra dati primitivi e oggetti. Quando il final viene applicato ai dati primitivi allora tale dato viene reso costante e il compilatore sostituisce ogni occorrenza di quel dato con il valore corrispondente. Quando la parola chiave viene applicato agli oggetti, invece, viene reso costante il riferimento all'oggetto ma l'oggetto stesso può essere modificato.
Java permette anche la creazione dei blank final, ovvero attributi dichiarati final ma non inizializzati e vengono inizializzati solo prima di essere usati. Questo è utile in quanto per istanze di oggetti diversi si possono avere diversi valori per l'attributo dichirato final pur mantenendo le caratteristiche del final.
Quando la parola chiave final viene applicato ai metodi allora si vuole indicare che tale metodo non deve essere specializzato ulteriormente e i metodi final vengono gestiti in modo più efficiente dal compilatore in quanto il compilatore chiama tali metodi con delle chiamate inline.
Il final applicati alle classi, invece, denota che quella classe è una classe foglia che non verrà specializzata ulteriormente.
